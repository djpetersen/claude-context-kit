# Prime a codebase

Produces two local, gitignored artifacts in the current repo:

- `graphify-out/` — a deterministic AST call graph, queryable
- `.claude/codebase-map.md` — a written orientation doc

Later sessions pick both up automatically because the user's personal
`~/.claude/CLAUDE.md` carries a standing rule to look for them (step 7).
Nothing is ever written into the repo's tracked files.

## Trigger

- "prime this repo", "map this codebase", "set up context here"
- Landing in an unfamiliar existing codebase before any planning skill
- `.claude/codebase-map.md` is missing, or its footer commit is far behind HEAD

## Steps

### 1. Preconditions

```bash
git rev-parse --show-toplevel   # must be a git repo; stop if not
graphify --version              # if missing, STOP and tell the user:
                                #   pip install graphifyy && graphify install
                                #   (macOS managed python: pipx install graphifyy)
git ls-files | wc -l            # tracked-file count
```

If `.claude/codebase-map.md` already exists, read its footer commit and compare
to `HEAD` (`git rev-list --count <footer>..HEAD`). Report how many commits stale
it is and re-prime; never silently trust an old map.

Report the file count plainly. Under ~200 files the map is still useful but the
graph adds little — say so rather than overselling it.

### 2. Build the graph

```bash
graphify update "$(git rev-parse --show-toplevel)"
```

**Give this call a long timeout** — 600000 ms. Indexing is fast on small repos
but can exceed the default two-minute tool timeout past ~1,000 files, and a
timeout here leaves a half-written graph.

Pure AST, no LLM, no network. Do NOT set `GEMINI_API_KEY` or `GOOGLE_API_KEY`
for this run — the code path must stay fully local. Expect a line like
`Rebuilt: N nodes, M edges, K communities`; report those numbers.

If it reports 0 nodes, the language is probably unsupported. Stop and say so —
do not write a map with an empty graph behind it.

### 3. Find the load-bearing modules

Read `graphify-out/GRAPH_REPORT.md`, then rank nodes by connection count:

```bash
python3 - "$(git rev-parse --show-toplevel)" <<'PY'
import json, collections, sys, pathlib
root = pathlib.Path(sys.argv[1])
g = json.loads((root / 'graphify-out' / 'graph.json').read_text())
if 'links' not in g and 'edges' in g:   # tolerate a schema rename
    g['links'] = g['edges']
lab = {n['id']: (n.get('label'), n.get('source_file')) for n in g['nodes']}
deg = collections.Counter()
for e in g['links']:
    if e.get('relation') in ('calls', 'imports', 'imports_from'):
        deg[e['source']] += 1; deg[e['target']] += 1
for nid, c in deg.most_common(20):
    name, src = lab.get(nid, (nid, '?'))
    print(f"{c:4d}  {name}  [{src}]")
PY
```

The top of that list is what breaks when it changes. It goes in the map.

### 4. Gather what the graph does not know

Read these directly — never guess:

- `package.json` / `go.mod` / `pyproject.toml` / `Cargo.toml`: scripts and key deps
- the dev, build and test commands, verbatim from scripts
- `tsconfig.json` path aliases, if present
- top two directory levels: `git ls-files | cut -d/ -f1-2 | sort -u`
- existing `README.md`, `CLAUDE.md`, `docs/` — summarize, never contradict
- entry points (`src/app`, `src/pages`, `main.*`, `index.*`)

### 5. Write `.claude/codebase-map.md`

Sections in this order, every claim grounded in something actually read:

1. **What this is** — one paragraph: stack, framework, what the app does.
2. **How to run it** — dev, build, test commands copied verbatim from scripts.
3. **Layout** — directory tree, one line per directory saying what lives there.
4. **Load-bearing modules** — the hubs from step 3, each with file path and what depends on it.
5. **Conventions observed** — naming, import style, path aliases, component patterns. Only what you can point at a file for.
6. **Open questions** — what could not be determined. Be honest; this list is the useful part.

Cite `path:line` wherever a claim comes from a specific place. End the file with:

```
<!-- generated by prime-codebase on YYYY-MM-DD from <commit sha> -->
```

### 6. Keep it out of the repo

Add the artifacts to the user's GLOBAL gitignore — never the repo's:

```bash
EX="$(git config --global core.excludesfile 2>/dev/null || true)"
[ -n "$EX" ] || EX="${XDG_CONFIG_HOME:-$HOME/.config}/git/ignore"
case "$EX" in "~/"*) EX="$HOME/${EX#\~/}" ;; "~") EX="$HOME" ;; esac
mkdir -p "$(dirname "$EX")" && touch "$EX"
for pat in 'graphify-out/' '.claude/codebase-map.md'; do
  grep -qxF "$pat" "$EX" 2>/dev/null || printf '%s\n' "$pat" >> "$EX"
done
git config --global core.excludesfile >/dev/null 2>&1 || git config --global core.excludesfile "$EX"

# verify each path individually — check-ignore exits 0 if ANY path matches
for p in graphify-out .claude/codebase-map.md; do
  git check-ignore -q "$p" || echo "WARNING: $p is NOT ignored"
done
```

The `case` line matters: git stores `core.excludesfile` verbatim, so a user who
set it to `~/.gitignore_global` has a literal tilde that the shell will not
expand inside quotes. Without that expansion the append fails silently and the
generated files stay visible to `git add -A` — which defeats the whole point.

### 7. Install the standing rule (once per machine)

If `~/.claude/CLAUDE.md` does not already contain a `## Codebase context`
heading, append this block:

```markdown
## Codebase context

Before planning or implementing in any repo, check for `.claude/codebase-map.md`
and read it if present — it is a generated orientation doc for that codebase.
If `graphify-out/graph.json` also exists, prefer it over Grep for structural
questions (what calls this, what depends on this, how does A reach B):

    graphify query "<question>" --graph graphify-out/graph.json
    graphify path "<SymbolA>" "<SymbolB>" --graph graphify-out/graph.json

Both are local, generated and gitignored. If the map's footer commit is far
behind HEAD, say so rather than trusting it.
```

This single block is what makes the context reach `/spec` and
`/plan-eng-review` — they read CLAUDE.md like every other session does.

### 8. Report

A few lines: tracked file count, graph node/edge count, the top three hub
modules, where the two files landed, and anything under "Open questions" worth
resolving before planning work starts.

## Verification

Confirm all four before finishing:

1. `git status --porcelain` shows no new tracked files — the repo is untouched.
2. `.claude/codebase-map.md` exists, and every command under "How to run it"
   appears verbatim in the project's scripts.
3. The graph resolved real symbols: pick a top hub (or a component the user
   named) and confirm `graphify query "<name>" --graph graphify-out/graph.json`
   returns it with a real `src=` path.
4. `~/.claude/CLAUDE.md` contains exactly one `## Codebase context` section.

If (1) fails, move the offending file and re-run. Never leave generated files
staged in a shared repo.
